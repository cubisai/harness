# Spec & plan review — 2026-09-25

A full review of `plan/docs/` and `spec/`, checked against the source (roughly 250 `file:line` references spot-checked, nearly all accurate) and the installed `@anthropic-ai/claude-agent-sdk@0.3.281` type definitions. All fixes below are already applied. This file records what changed and why, because `spec/` is untracked and has no git diff.

## Wrong facts or unfalsifiable tests

- **T0.7.** The "seq race / O(n) scan" claim was wrong. `MAX(seq)` over the primary key is an index seek. `node:sqlite` is synchronous, so two `Store`s in one thread can't interleave, and the proposed test would pass against the old code. Deltas are never persisted either. The task is now labelled hardening, and the test uses `worker_threads`.
- **T0.9.** The spec said ubuntu only and no Codex. That contradicted Ch. 6 §6.5 and root `README.md:143`. CI is now a 3-OS `test` matrix plus a separate Linux job that installs Codex. Tests stay gated on the binary being present.
- **New T0.10.** Component tests (`renderToStaticMarkup`) were specified in phases 1, 3, 6 and 7, but Vitest only collects `*.test.ts` and `tsconfig.node.json` has no `jsx` setting. This task enables `.tsx` tests.
- **T0.4.** Codex `inputTokens` includes cached tokens, so net-new input now equals `inputTokens − cachedInputTokens`. ACP was reporting `usage_update.used` (context occupancy) as input. Both are fixed.
- **T3.7 / S1 / S4.** `Query.setModel()` only works in streaming input mode, and the Claude driver uses a string prompt for each turn, so the method can't be reached. Codex already sends `model` on `turn/start`, so S4 now asks whether the model change takes effect.
- **T3.8.** `service.ts` has no `driver.id` branches, so the old test proved nothing. The actual branches are in `library.ts:75/82`.
- **T3.1.** The "preset is a floor" rule contradicted T3.4. `initialize` now decides protocol capabilities.
- **T3.5.** The ACP judge only sees commands the agent asks permission for, so generic ACP stays `warnOnly`. It now answers `reject_once`, not `reject_always`. The load location for the OpenCode plugin was unspecified and is now covered by S8.
- **T5.2 / T3.9 / Ch. 4 §4.3.** MCP reloads already happen at the start of a turn, so "queue to a turn boundary" saves nothing. Removing the trigger (T5.3) is what saves money. T5.2 now batches edits and classifies each reload as an expected rebuild. T3.9 owns the notice.
- **T5.1.** The harness doesn't build agent requests, so it can't control where their cache breakpoints go. The scope is now stated.
- **T5.4.** The miss threshold is per request in Claude Code but per turn here. The difference is now noted.
- **T8.5/T8.14.** "Computed style" acceptance needs a DOM, which the suite doesn't have. These are now CSS and settings assertions plus a manual preview check.
