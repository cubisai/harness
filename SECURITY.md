# Security

CubiQ can run agents, commands, and MCP tools against local projects. Use trusted integrations, review permissions, and keep backups of important work. Permissions and sandboxing differ between agents; do not assume every integration enforces the same protections.

## Reporting a vulnerability

Do not post credentials, private code, personal paths, or exploit details in a public issue.

Use the repository’s **Security → Report a vulnerability** option when private vulnerability reporting is available. Otherwise, open an issue requesting a private reporting channel without disclosing sensitive details.

Once a private channel is established, include the affected version and platform, a minimal reproduction, expected impact, and any proposed mitigation. Redact secrets and use a disposable sample project.

## Versions

The project is in early development. Please reproduce reports against the latest available version; fixes are generally made on the active development branch.
