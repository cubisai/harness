# CubiQ reliability and product plan: Chat, Code Mode, Design, and Creator

**Revised 2026-11-27 · proposed.** Ship the **Alt+Enter checkout fix** first. In a Git project, “Own worktree” promises a separate branch, but the composer can send the task to the project checkout even when no plugin is selected. Stop does not undo edits already made there. Next, give every accepted send an owner and a definitive outcome. The composer needs to know *whether work was accepted*; an automation needs to know *how that work ended*, including any automatic fix round.

## 1. Keep work in the intended checkout and thread

[Turn-ownership verification, November 27](.ai/tmp/turn-ownership.adsQdB/verification.md): both handoff channels, question deletion and post-fix sends exercised through the Electron UI with scripted drivers; the timing and ownership assertions are in `test/switch.test.ts`, `test/service.test.ts` and `test/run-limit.test.ts`.

- [x] **Honor the background worktree setting.** Resolve the explicit `worktree` field first, including `false`, then the background preference; forward skill/command identities unchanged. Exercise Alt+Enter with the setting on/off and with empty selections, a skill and a plugin command. In a Git fixture check the stored branch, driver working directory and resulting file contents. If a requested worktree cannot be created, no driver starts and no edit lands in the project. Built-in Chats keeps its existing [private folder without a branch](src/main/service.ts#L323-L359). [Git's worktree manual](https://git-scm.com/docs/git-worktree) distinguishes per-checkout files and `HEAD` from shared repository data; this is checkout isolation, not a separate repository. [Electron results](.ai/tmp/composer-checkpoint.MgKN33/verification.md).
- [x] **Reserve a turn before yielding.** In [`Service.send` and `waitForSlot`](src/main/service.ts#L849-L892), the busy check precedes an `await` even when a slot is free. Reserve the thread synchronously. A queued send owns its thread, but consumes no execution slot until admitted. Count an admitted send exactly once through dispatch and automatic check/fix rounds; only its owner can complete it and release the slot. Extend [the run-limit tests](test/run-limit.test.ts): same-tick sends to one idle thread admit exactly one; two threads competing for one background slot start in order; Stop while queued never dispatches; a refusal frees any reservation. Foreground work still bypasses the background limit, and limit `0` still means unlimited across different threads.
- [x] **Settle work before deleting its thread or project.** A deleted running thread threw during final cleanup and remained in `isRunning`; an asynchronous question outlived its deleted thread. In [the service](src/main/service.ts), block new admission during deletion, settle requests and follow-up messages, and release the slot even if the database row has gone. Test deletion during a turn, while queued, and with an unanswered async question. An async question should still survive an ordinary turn end.
- [x] **Pin handoffs to the originating operation.** A delayed seed for agent B wrote its session cursor into agent C after a second switch. Reserve the thread through checkpoint preparation and seeding; only update the intended agent binding while that operation is current. Exercise both item injection and first-message seeding, including Stop and a concurrent Send or switch. See [`switchAgent` and `seedHandoff`](src/main/service.ts) and [session binding writes](src/main/db.ts).
- [ ] **Repair native session history before appending.** [SessionStore](src/main/harness/session.ts) stops reading at a torn JSONL line; [the provider driver](src/main/harness/driver.ts) can then append behind it. Use the existing atomic replacement path for a damaged tail. Cover a final assistant message with several tool calls when only some results landed; preserve complete exchanges and never replay a tool side effect to fill a gap. Crash → resume → append → resume again must retain the new messages and a valid model history. For older files with valid records after a malformed line, preserve the original before attempting recovery; a failed repair must not destroy those later records.

## 3. Make automations, memory, and connections recover correctly

- [ ] **Use the run's actual outcome.** Replace [`sendAndWait`'s idle polling and transcript scan](src/main/automations/app.ts#L63-L80) with the completion result from §1, including that send's automatic check/fix rounds. Partial text remains readable in the thread. A provider error or a required check still failing after its allowed rounds yields `failed`; explicit Stop yields `cancelled`; exceeding budget retains `paused-budget`. A failed or user-cancelled run cannot publish a success or advance a source bookmark. Test a successful fix round and an unrelated later send on the same thread.
- [ ] **Pin queued automation settings.** The [store](src/main/automations/store.ts#L263-L274) records `configVersion` at claim; the [runner](src/main/automations/runner.ts#L211-L232) reads today's settings. Cancel a stale queued claim with a visible reason before dispatch, including after restart. Test edits to the prompt, budget and permission mode. Preserve the distinction between schedule Off (no scheduled work; a fresh manual run is allowed) and plugin Off (neither scheduled nor manual work is allowed).
- [ ] **Make delivery recoverable.** The [runner](src/main/automations/runner.ts#L307-L323) confirms a receipt, advances bookmarks, then finishes the run in separate writes; the local destination's receipt lookup also depends on process memory. For Message Center, commit the receipt keyed by run and destination, result text, terminal outcome, usage and eligible bookmark advances in **one SQLite transaction**; notify the renderer after commit. On reload, rebuild the view from durable records. Repeating a delivery notification must not create a second copy of the result.
  - For the [destination interface](src/main/automations/io.ts), persist the intent and checkpoint together before an external publish. After a crash, reconcile by the same key: confirm a known delivery; retry only a definitely missing, safely repeatable publish; keep an unknown result visible without reposting. A local transaction cannot prove what another system received. See [SQLite's transaction guarantee](https://www.sqlite.org/transactional.html) and [AWS on idempotent retries](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/).
  - Recover legacy confirmed receipts too: [`pendingDeliveries`](src/main/automations/store.ts#L396-L400) currently excludes them. Store the bookmark read as well as the proposed next value; advance only if the source still has the expected value. [Git bookmarks are commit IDs](src/main/automations/sources.ts), so sorting their strings cannot establish order. Test a crash on both sides of each commit and publish, restart twice, and preserve a newer bookmark. If an old checkpoint cannot establish its outcome or cursor safely, surface that uncertainty.
- [ ] **Fix the scheduling clock.** Calculate the latest eligible instant without enumerating 10,000 missed ticks. Keep manual run history separate from the scheduled cursor: [`lastScheduled`](src/main/automations/store.ts#L276-L280) currently includes both. Preserve the tested skip grace of 60 seconds and the existing first-valid-minute / first-occurrence policy for wall-clock jobs. [IANA's Europe rules](https://data.iana.org/time-zones/tzdb/europe) establish the Berlin offset transitions; CubiQ's [scheduler tests](test/automation-schedule.test.ts#L50-L99) establish what to do with them.

  | Regression input | Observed this revision | Required result |
  | --- | --- | --- |
  | One-minute interval; last tick and anchor Jan 1 00:00 UTC; wake Jan 9 00:00 UTC, 2026 | `skip`: none; `coalesce`: Jan 7 22:40 UTC | Exactly the Jan 9 00:00 tick under either policy. A second scheduler tick cannot claim it again. |
  | `Europe/Berlin`, daily 02:30, March 29 / October 25, 2026 | March: 00:59 UTC; October: 01:30 UTC | March: **01:00 UTC** (03:00 local). October: **00:30 UTC** (first 02:30), once only. |
  | Five-minute interval anchored at 00:00 UTC; Run now at 00:05:10; scheduler ticks at 00:05:30 | Runner claimed zero scheduled runs, versus one without Run now | Keep the manual run and claim the 00:05 scheduled run once. Neither consumes the other's identity. |

- [ ] **Make opt-out and user decisions take effect immediately.** [Memory extraction](src/main/memory/extractor.ts) called its model after Memory was disabled during debounce. Recheck at dispatch and before saving; cancel queued work and discard revoked results. [Lesson verification](src/main/learn/index.ts) reactivated a lesson dropped while verification was running. Apply the verdict only to the still-eligible lesson revision. Test Off while queued/in flight, and Drop or Retire before a late verification result.
- [ ] **Keep connector sign-in through temporary outages.** [OAuth refresh](src/main/mcp/oauth.ts#L485-L534) clears saved tokens on any current refresh exception and can return the captured access token before its expiry. [RFC 6749 §5.2](https://www.rfc-editor.org/rfc/rfc6749#section-5.2) defines `invalid_grant`; an offline error, 429 or 5xx does not establish revocation. Retain refresh credentials after a transient failure, never return an expired token, and require sign-in after definitive rejection without returning the captured token. Test retry after recovery and late completion after sign-out.
- [ ] **Reserve local issue numbers before writing files.** Two concurrent [local issue creations](src/main/issues.ts) both returned issue `1` because their titles produced different filenames. Reserve a unique number per project before copying attachments or publishing the issue. Test concurrent creates and failure after reservation; each visible issue must have its own number and attachments.

Ask for two edits to the same fixture: approve the second first and verify the final file reflects invocation order; deny the first and verify only the second runs. Every displayed child row settles once. Independent reads can still overlap.
2. [ ] **Enforce the advertised file scope and state quota.** Apply the external wrapper's thread-folder scope to file tools, including reads through `readMany`; resolve against the canonical root before dispatch. Test two concurrent scripts whose changes fit individually but exceed the quota together: only a complete change set that fits may commit. Abort or refusal preserves the previous values.
3. [ ] **Make “Applies to new threads” survive restart.** The [mode cache](src/main/code-mode.ts#L39-L48) lasts one process. Persist the effective mode when a thread is created. For a legacy thread with no value, resolve once on first use and retain it. Make the [Settings copy](src/renderer/src/components/SettingsSheet.tsx#L518-L530) describe the native and external tool lists accurately.
4. [ ] **Make Stop work during computation.** The earlier runner probe saw a CPU-bound evaluation delay the host event loop. Completed edits remain visible.
5. [ ] **Return usable discovery results.** The [MCP router](src/main/mcp/router.ts#L396-L430) appends server warnings to JSON text. 6. ## Coverage and verification

For every fix, first capture the failing transition in the nearest existing suite, then rerun it through the entry point users actually use. Use deferred promises, fake clocks, and restart fixtures for deterministic ordering. For renderer changes, follow [DESIGN.md](DESIGN.md).

| Feature family | End-to-end check before marking it verified |
| --- | --- |
| Agents, providers, threads, and usage | Create, send, stream, compact, Stop, switch agent/model, resume, and compare the transcript, usage, and Message Center with the actual turn. Include permission, plan, and question cards during reload. |
| Code workspace | Send attachments and project skills; inspect files and diffs; exercise the configured check and fix rounds; review worktree commit/merge/push against an isolated fixture. Verify the selected checkout and editor target. |
| Browser, terminals, and artifacts | Take over a browser while two threads run; switch projects with terminals open; inspect current and older artifact versions; retry a timed-out document preview. |
| Library and Creator | Start blank → choose a template → resume draft → play offline and success scenarios → review evidence → install. Edit and recheck an update; verify Off/On, uninstall, connector sign-in, expert/team runs, and theme preview/apply/revert. A late result cannot reactivate a disabled contribution. |
| Design Studio | Generate or load a page, edit, undo/redo, handle an external edit, compare variants and widths, send comments, play a named flow, restore a version, and export HTML/PNG/PDF. Build a pinned revision from a worktree and compare the build inputs with the reviewed files, including assets. |
| Background and desktop | Exercise automation recovery, budgets, memory opt-out, lesson verification, startup/restore, settings, diagnostics, and update retry. Record native platform and provider coverage separately from mocks. |

After focused regressions, run `bun run typecheck`, `bun run test`, `bun run design:check` and `bun run build`. Distinguish the two smoke checks in the verification record:

- **Local build:** [`bun run smoke`](package.json#L25-L30) runs `electron . --smoke` against the local build. Use `bun run smoke --user-data-dir=<disposable-profile-path>` for an isolated local check.
- **Packaged app:** follow the [CI smoke job](.github/workflows/ci.yml#L74-L92): after build, run `bunx electron-builder --dir --publish never`, then `node scripts/build/smoke.mjs` (`xvfb-run -a` on headless Linux). The [launcher](scripts/build/smoke.mjs#L9-L27) selects an existing artifact under `dist/`; use the artifact from this build. Record platform, app version, driver and which journeys used real providers or native processes. Passing one smoke check does not establish the other.
