## P4.1 Background runs: shared accounting, budget, explicit model
Evidence: extractor calls `driver.oneShot` with no usage recorded and no cap (memory/extractor.ts:235-243); lesson drafts record tokens to learn_budget (learn/index.ts:271, learn/db.ts:217-222); explicit Settings background model (learn/background.ts:45-50) is ignored by the extractor.
Change: `background_runs` table (purpose, project, day, agent, model, tokens, estimated, ok, at) + LearnDb.recordRun/runTokens; extractor records every run (tokens estimated 4 chars/token), skips when today's memory tokens ≥ `LearnSettings.memoryDailyTokens` (default 200,000, clamped like dailyTokens), and uses the explicit background model pick (per project, then global) via backgroundShot when one is set; otherwise today's pick + fallback, the fallback recorded as `escalated`. Lesson drafts also record runs (learn_budget unchanged).
Blast radius: extractor deps gain optional hooks (absent = today's behaviour, tests pin); new migration only adds a table.

## P4.2 Scope-aware extractor dedupe
Evidence: extractor sees only the project index and updates/deletes project notes only (extractor.ts:179-196, :236, :245); write tool already does same-name/Jaccard dedupe and project-then-global lookup (memory/tool.ts:190-206).

## P4.3 Relevance-ranked retrieval with correction priority
Evidence: blockIndex ranks by recency only (memory/store.ts:299-338); memory_read query = substring word counts (memory/tool.ts:103-119); no correction notion.
Change: sidecar `kind: "correction"` (set by extractor/write tool when the note supersedes another); corrections always listed first within scope; memory_read query ranking via BM25 over name/description/body with path/recency tie-breaks.
