## P5.1 Auto-open on browser tool use + readiness wait
Today every tool answers "Browser pane not open" until the user opens the pane (tools.ts gated); page() can already request opening and wait 15 s for attach. Change: gated opens the pane (controller.ensureOpen → page()) and waits for attach + load to settle; the open timeout injectable; refusal text only when opening fails.
## P5.2 Backend interface + headless agent-browser adapter (pinned CLI)
`BrowserBackend` interface from the controller's surface (open/navigate, snapshot, click, type, eval, logs, screenshot, close); BrowserController implements it; `AgentBrowserBackend` shells out to `agent-browser` (version checked, isolated --session per job), same snapshot/ref text shape.
## P5.3 Session ownership + per-target serialization
Visible pane = one target owned by the thread that last drove it; other threads' mutations wait (per-target mutex) or are refused with an actionable message; headless jobs get their own backend instance/session. Takeover stays global for the visible pane.
## P5.4 Readiness conditions, stale-ref recovery, compact observations
Replace the fixed 250 ms settle with load/URL/selector conditions (`wait_for` arg); snapshots carry a page version so a ref from an older snapshot is detected as stale instead of silently retargeting; scoped snapshot (selector) and logs since last read.
## P5.5 Dev-server lifecycle + test reports
Detect a running dev server (package.json scripts + port probe), start an owned one through the normal run policy when asked, track and stop only owned processes; a `browser_report` result shape (assertions, actual, logs summary, screenshot refs).

### P5.4 spec (2026-10-19, Mac)
Shared contract in `src/main/browser/backend.ts`: `WaitFor { url?, selector?, text?, timeoutMs? }` (5 s default, 30 s max), `waitScript`/`waitUntil`/`waitNote` (one in-page promise, retried across a navigation until the deadline), `SnapshotOptions { selector?, interactive? }` + `scopeLines`, `staleRefMessage(ref, print, matches)`, `NO_LOGS`/`NO_NEW_LOGS`. Interface: `open(url, device?, wait?) → wait note`, `snapshot(opts?)`, `click(ref, wait?)`, `type(…, wait?)`, `logs(clear, newOnly?)`.
- **Readiness:** browser_open/click/type take `wait_for`. With it, the visible pane skips the fixed 250 ms sleep and waits on the condition; the result gains "Waited N ms for …" or "…: not met. Now at <url>". Without it the old settle is unchanged.
- **Stale refs (visible):** collectPage keeps an element's ref across snapshots and numbers new elements from a per-controller counter that never resets, so a ref is never reused for another element, even after navigation. The controller remembers each ref's kind+name. A missing ref takes a fresh snapshot and names the same-kind-and-name match ("use that ref if it's the one you meant"); it never acts on a guess.
- **Stale refs (headless):** agent-browser renumbers e1… per snapshot (probed on 0.35.2). The adapter hands out its own refs, offset by the count issued so far and mapped to the latest snapshot's CLI refs; an older ref → staleRefMessage with matches from a fresh snapshot.
- **Compact:** browser_snapshot `selector` (scope) and `interactive` (refs only); browser_logs `new_only` (since the last read). Defaults are unchanged.
- Tests: backend helpers (pure), controller with a fake CDP (wait/no-wait settle, stale message, log delta), the adapter against a fake CLI, and real-browser checks through agent-browser (collectPage stable refs and scope on a data: page; delayed text with wait_for) when the CLI is installed, on any platform.
