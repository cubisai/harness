Source: plan/docs/13-harness-optimization-roadmap.md §5.3, §5.4, P3. Research: harness-roadmap/.ai/research_notes/roadmap13-p3.md (spot-checked).
Rules: one commit per point; typecheck + full vitest (compared against the env-failure baseline) before each; old behaviour pinned by tests; live turn on Claude/Codex/OpenCode Zen at phase end.

## P3.1 Tool effects separate from permission
Evidence: loop batches by `access === "read"` (src/main/harness/loop.ts:231-233); app tools get `access: autoAllow ? "read" : "edit"` (driver.ts:487), so auto-allowed mutating tools (browser_click/type/open, memory_write, team_write/post, design_critique_save, ask_user) run in parallel read batches.
Change: `HarnessTool.effect?: "read" | "mutate"` (absent = legacy: autoAllow → parallel). `LoopTool.parallel?: boolean` (absent = `access === "read"`, the legacy rule). Batching uses parallel; permission keeps using access. Mark every app tool's effect. Expose `readOnlyHint` annotations to Claude (SDK tool extras) and the HTTP MCP tool server (mcp-http.ts) for effect-marked tools.
Blast radius: loop scheduling only; permission decisions unchanged (test pins); tools without effect keep today's batching (test pins).

## P3.2 Skill catalog index + search above a threshold
Evidence: skillTool lists every skill as `- name: description` (src/main/skills/tool.ts:19-25), no total cap, no search.
Change: above a threshold (> 40 model skills or > 6,000 chars of listing), the skill tool description lists names only (grouped compactly) and gains a `query` mode that ranks skills by name+description (reuse the BM25 in mcp/router.ts rankTools via a shared helper); exact-name load unchanged. Catalog snapshot pinned at session (tool construction) time. Below threshold: byte-identical description (test pins).

## P3.3 MCP catalog persistence, cold refresh, unavailable ≠ no match
Evidence: McpToolsCache in-memory only (mcp/servers.ts:476-519); search_tools drops failed listings silently (router.ts:266-272).
Change: optional persistence of non-secret listings (spec hash → tools, at) to a JSON file in userData; loaded at startup as "stale" entries usable for router descriptions/ranking while refresh runs; search_tools results name servers that couldn't be reached separately from "no match".

## P3.4 Result references for MCP/browser outputs
Evidence: bound() applies to native tools only (tools/bound.ts; driver.ts:496 app results unbounded); no harness-output cleanup.
Change: appLoopTool bounds app tool text through bound() (MCP + browser results get the same saved-file reference); startup prune of harness-output files older than 14 days.

## P3.5 Code-mode pilot (flagged)
Evidence: no sandbox in repo; no flag system beyond Settings fields.
Change: decided when reached (likely `quickjs-emscripten`, pinned, behind `Settings.codeMode: "off" | "on"` default off, native harness only, every brokered call recorded as a child tool-use).
