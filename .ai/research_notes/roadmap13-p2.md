## Findings
- **Task so far**: read-only mapping of CubiQ code for roadmap phase P2 "app responsiveness"; deliverable is a ~250-line Markdown report with one section per P2.1–P2.7, each ending with "Tests that pin current behaviour:". No files were modified. Baseline from `road-map-handoff.md:127,131`: `listEvents` 10k = 104 ms, 50k = 636 ms / 45 MB event JSON; `segmentEvents` ~33 ms.
- **P2.1 — history load**: the whole thread's events are loaded in one shot through IPC `events:list` → `Store.listEvents`, which does a single ordered scan and `JSON.parse`s every row. Events table's only key is `(thread_id, seq)`; grep of `db.ts` found indexes only on `turn_scores` and `lessons` plus the `search_fts` virtual table — **no index on `events.created_at`** (so `turnUsage` is a full scan). During a turn each event is persisted with sync SQL then broadcast one at a time. No "find in thread" feature exists.
- **P2.2 — event grouping**: `turns.ts` `segmentEvents` folds runs of tool calls into "work" segments and attaches answer/prompt/changes to `turn-end`. The `tool-result` lookup map and `parentId` grouping into subagent "children" happen in `ThreadView.tsx`, not in `segmentEvents`.
- **P2.3 — transcript render**: `ThreadView` renders every segment via `segments.map` — **no virtualization/windowing** (grep for `react-window`/`virtuoso`/`@tanstack/react-virtual` returns nothing in the renderer except ArtifactPanel's own overscan math). Auto-scroll uses a `pinned` ref; row keys are `w{key}` / `e{seq}`. No in-thread search UI (grep found none).
- **P2.4 — boot**: renderer `init()` fires 7 calls in `Promise.all`, then loads threads **sequentially per project** (`for … await listThreads`), then selects the first project and its most recent thread, which awaits `listEvents` for that thread. Main-process startup constructs `Store` synchronously after `whenReady`, defers `pruneBlobs` via `setImmediate`, and kicks the MCP tool server with `void`.
- **P2.5 — caches**: `events`, `live`, `artifactFiles`, `turnScores`, `designReload` are per-thread maps. They are loaded lazily and kept; the **only place `events[threadId]` is dropped is `deleteThread`**. No LRU/eviction found.
- **P2.6 — session store**: `SessionStore` uses synchronous fs (`appendFileSync` on the `onMessage` hot path, `readFileSync` on load, `writeFileSync`+`renameSync` for atomic meta/replace).
- **P2.7 — design watcher**: `DesignWatcher` debounces changes, ignores `comments.json` / `.tier`, is ref-counted, and reports only a `threadId`; main broadcasts `{ type: "design-changed", threadId }` — **changed file paths never reach the renderer**. Renderer bumps `designReload[threadId]` and the canvas/board re-fetch.
- **Tests located** for pinning behaviour: `turns.test.ts`, `live.test.ts`, `design-watch.test.ts`, `design-canvas.test.tsx`, `history-fixtures.test.ts`, `harness-driver.test.ts` (SessionStore), `db.test.ts`, `service.test.ts`, `render-parity.test.tsx`, `composer.test.tsx`, `codex-subagent-render.test.tsx`, `collapse.test.tsx`, `health-dot.test.tsx`.
